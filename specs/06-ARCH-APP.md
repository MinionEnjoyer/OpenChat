## 2. Package layout (enforced by ESLint `import/no-restricted-paths` — arrows are the ONLY allowed dependency directions)

```
apps/mobile/src/
  api/        typed REST client (generated schema + fetch wrapper, auth header, request-id, refresh interceptor)
  realtime/   gateway client: connect/ticket, heartbeat, backoff, subscribe registry, typed event emitter
  sync/       glue: gateway events + REST responses → query-cache writes (THE only module allowed to call queryClient.setQueryData)
  domain/     pure logic, zero RN imports: permissions (shared source w/ api — see §4), markdown AST, mentions, unread math, pagination merge, time/format
  stores/     zustand stores
  features/   <feature>/screens|components|hooks (auth, shell, messages, servers, social, media, voice, settings, notifications)
  ui/         design-system primitives (tokens, Text, Button, Sheet, Toast, Avatar…)
  lib/        logger, config, storage, deep-links, clock (E2E-freezable)
  navigation/ navigators + linking config
```
Dependency rule: `ui`/`domain` import nothing app-level; `features` never import each other's
internals (only their public `index.ts`); `sync` is the single writer to server-state cache.
Violations are lint errors, not review comments.

## 3. Data & sync model (the load-bearing design)

- **Query keys (canonical, exported from `sync/keys.ts`)**: `['me']`, `['servers']`,
  `['server', id]`, `['channels', serverId]`, `['members', serverId]`, `['roles', serverId]`,
  `['messages', channelId]` (infinite), `['pins', channelId]`, `['dms']`, `['friends']`,
  `['notifications']`, `['presence']` (Map userId→status), `['voice', channelId]`.
- **Reads**: screens use queries only; no screen fetches imperatively.
- **Writes**: mutations with optimistic updates copied structurally from the web client's
  behavior (Phase-0-verified), keyed reconciliation:
  messages by `nonce` (FR-MSG-002); everything else by id.
- **Gateway → cache**: `sync/applyEvent.ts` is an exhaustive `switch` on the generated event
  union (compile error when contracts add an op): `message.created|updated|deleted` patch the
  infinite pages; `presence` patches the presence map; `typing` feeds a TTL store (5s);
  `notify` invalidates `['notifications']` + `['servers']` (coarse — matches current backend,
  E3) until FR-SRV-009 granular events replace specific invalidations; `mention` increments
  unread store + local toast.
- **Reconnect** (`realtime/connection.ts`): exponential backoff 1s→32s + full jitter (NFR-07);
  on `ready`: resubscribe the subscription registry, then invalidate all active queries
  (missed-event repair — correctness beats elegance given no event replay upstream).
- **Subscriptions**: subscribe to the visible channel + all channels of the active server +
  all DM channels (matches web behavior — verify exact web policy in Phase 0 E2 and mirror it;
  record in a comment with the E-ref).
- **Unread model** (`domain/unread.ts`): pure function of (ReadStates, message ids, mention
  events) → per-channel {unread, mentionCount}; unit-tested exhaustively (FR-MSG-010); the
  server remains authoritative via `POST read`.

## 4. Sharing the permission calculator (FR-ROLE-002)
Create package `packages/shared-domain` (workspace) containing `permissions.ts` MOVED from
`apps/api/src/permissions/` (api re-exports from the package — verified by characterization
tests staying green) plus mention/markdown token rules shared with web later (P2). Mobile
imports the same code the server executes. BigInt-safe serialization helper included
(`permissions.json` codegen consumes this package).

## 5. Cross-cutting policies
- **Errors**: `api/` normalizes every failure to `ApiError {status, code?, requestId,
  retriable}`; mutations show toast + retry per FR-APP-006; queries render the four states
  (04 §7). No naked `catch {}` — lint rule.
- **Auth lifecycle**: single-flight refresh; queue concurrent 401s behind it; hard-logout
  broadcast on refresh failure (FR-AUTH-010).
- **Clock**: all `Date.now`/timers via `lib/clock` (E2E freeze, 04 §6).
- **Config**: `GET /api/config` fetched at boot, cached, typed; feature flags (giphy, share)
  derive from it — UI hides gracefully when absent (matches web behavior).
- **Theming**: token-based (`ui/tokens.ts`), dark default, light + system (FR-APP-004);
  no raw color literals outside tokens (lint).
- **Strings**: `ui/strings.ts` module (NFR-11).

## 6. Persistence & offline (exact scope — NFR-05/06)
Persist: session store · ui prefs · query cache ONLY for keys `['servers']`, `['dms']`,
`['channels', *]`, and the newest page of `['messages', c]` for the 10 most-recent channels
(LRU, maintained by `sync/persistPolicy.ts`). Outbound queue: `stores/outbox` (max 50 sends,
FIFO, per-channel ordering, survives restart, drains on `ready`). Everything else is
network-fresh. Do not grow this list without a Decision Record.
